# 表是怎么来的：从官方客户端生成签名用的表（方法说明）

本文把"签名实现所需的表与常量"的**生成链条**写清楚，使读者能在**自己那份官方客户端**上重做一遍。
本仓库不分发表数据、不分发脚本、不分发客户端——只描述流程、输入、输出与自校验点。

> 适用范围与版本绑定见 `../NOTICE.md`；失效条件见 `signature.md` §7。

## 1. 链条总览

```
[你自备] 同代官方客户端（Windows）
   │
   ├─(a) 取 .text 内存镜像（本代 2 809 856 字节）           → blob
   │      并确定其中被改写的那 8 字节：明文 → 密文
   │
   ├─(b) 模拟执行客户端机器码，用"单比特探针"提取线性	map  → PACK / UNPACK 系数
   ├─(c) 反汇编 P2 的轮程序，得到有序步骤表              → STEPS（逐条表达式）
   ├─(d) 从客户端数据区取常量表                          → MIXT / KEYTAB / Whirlpool 表+轮常量
   │      （Tiger 的 S 盒与标准 Tiger 相同，可直接用公开实现）
   │
   ├─(e) 用 (a) 的 blob 计算三个"镜像摘要"常量            → DIGEST_MD5 / DIGEST_SHA1 / DIGEST_TIGER
   │
   └─(f) 生成表源文件（数组 + 展开后的轮函数）             → win_v3_tables.{c,h}
         并用 vectors/vectors.json 做终检
```

## 2. 每一步的输入、输出与自校验

### (a) 取得镜像与那 8 字节

- 客户端在哈希前会取**自己映像的第 2 个区域（`.text`）整段拷出**；本代长度 2,809,856 字节。
  取得方式：在受控环境里读取该区域（或按同样规则自二进制重建），随后**逐字节校验长度**。
- 镜像中有一处 8 字节会在哈希前被块密码改写：明文 `0000005081ec8c00` → 密文 `853eac23ac4931ff`。
  **该变换的算法本笔记尚未复刻**；生成表时按同样方式从你自己的客户端取得这 8 字节即可。
- 自校验：`len(blob) == 2809856` 且 `blob[0x400:0x408] == 明文`（在你替换之前）。

### (b) 提取线性 map（PACK / UNPACK）

- 位打包/解包是**按位线性**的（只有 and/shl/shr/or，无查表无进位）。
- 做法：**单比特探针**——让输入中每次只有一位为 1，观察输出；所有探针合起来就是系数矩阵。
  为省时间可只跑一遍模拟执行并按位采样，而不是真的跑几千次。
- 自校验（重要）：**全零输入必须得到全零输出**——这证明 map 里没有常数项；若有非零常数项，说明采样方式错了。

### (c) 反汇编 P2 的轮程序（STEPS）

- P2（改版 MD5）的轮逻辑用在"多轮 + 影子槽 + 递增常量"的方式实现，直接照抄机器码最稳。
- 做法：反汇编该函数 → 输出**有序步骤表**（每条是纯表达式，例如 `a = b + rol(...)`) → 再机械地展开成源码。
- 自校验：把展开后的函数与真机码在若干输入上逐字节比较（见 (f) 的终检）。

### (d) 常量表

| 表 | 位置（相对客户端） | 备注 |
| --- | --- | --- |
| `MIXT`（8×64 u32） | 与该变换函数同一代码块附近 | 厂商改动，必须提取 |
| `KEYTAB_V2` / `KEYTAB_V4`（各 128 字节轮密钥表） | 同上 | 由种子决定；两个变体各一份 |
| rjv3 版 Whirlpool 的 8×256 u64 表与 11 条轮常量 | 客户端只读数据区（表区约 16 KB） | **其中 C0/C3/C7 有 63 字节偏离教科书**，必须提取 |
| Tiger 的 S 盒（4×256 u64） | — | ✅ **与标准 Tiger 逐项相同**，可直接用公开实现（例如 minieap 的 `rjtiger_sbox.c`），无需提取 |

### (e) 三个镜像摘要常量

用 (a) 里**已改写**过的 blob 计算：

- `DIGEST_MD5` = P2 对整段 blob 的输出（16 B）
- `DIGEST_SHA1` = P1 对整段 blob 的输出（20 B）
- `DIGEST_TIGER` = P3 对整段 blob 的输出（24 B）

> 这三个常量就是"镜像指纹"。它们与镜像一一对应：镜像变了，它们必须重算。

### (f) 生成表源文件与终检

生成物是一对 `{c,h}`：

- `h`：11 个表/常量的 `extern` 声明 + 轮函数原型；
- `c`：数组定义 + **展开后的轮函数**（把 STEPS 变成顺序赋值语句）+ 三个摘要常量。

终检（缺一不可）：

1. 把 `vectors/vectors.json` 里**每个**向量喂给你的完整实现，与 `expected_digest_hex` 逐字符比较；
   优先保证 3 条 `official` 向量全中（它们才是"与官方一致"的证据）。
2. 抽查已知边界：padding 分支（输入位长 ≥ 32 字节时走**两块**）、空输入、长度恰在块边界的情形。
3. 记录你使用的客户端指纹（版本 + 二进制 MD5 + `.text` 长度），写进你自己的仓库——**换版本时必须重做整条链**。

## 3. 已知缺口与注意事项

1. **8 字节块密码的算法未复刻**：只知其确定性输入/输出。这意味着"(a)"这一环目前必须依赖从客户端取值，不能纯静态推导。
2. **表区定位要靠锚点**：客户端里表区与代码的相对关系是本代次的观察结果，换版本可能整体位移。
3. **不要把生成器写进第三方仓库的工作树**：生成器如果把产物直接写进某个上游项目目录（例如 minieap 分支），发布时会同时混入第三方代码与许可问题——建议生成到独立目录，再显式拷贝。
4. **不要提交生成输入**：`.text` 镜像、提取出的表、以及客户端任何片段都不应进公开仓库；公开的只有"算法结构 + 方法 + 向量"。
