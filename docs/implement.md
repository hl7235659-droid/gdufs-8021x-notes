# 怎么把它接进 minieap（行为学要点，不是补丁文件）

本文件描述的是**需要让客户端具备哪些行为**，以及每一条为什么必要。
落到代码时请自行在 [updateing/minieap](https://github.com/updateing/minieap) 及其
[广外适配分支](https://github.com/jimlee2048/minieap-gdufs) 上实现——本仓库不提供补丁或二进制。

## 1. 七条行为学要点

| # | 行为 | 为什么必要 | 不做会怎样 |
| --- | --- | --- | --- |
| 1 | **追加私有段后同步两个长度字段**（EAPOL length 与 EAP length，大端）= `实际帧长 - 14 - 4` | 服务器严格按长度读取；早期实现注释里写着 "vendor extension does not get counted here" | 帧看起来 567 字节，服务器只读 33 字节 → **整个私有段被当填充丢弃**（历史根因） |
| 2 | **私有段只加在 EAP-Response/MD5 上** | 官方 Identity 应答是纯用户名 | 长度修正后服务器会真的去解析 Identity 里的私有段并拒绝 |
| 3 | **`modify_*_prop_list()` 返回的是长度增量，不是绝对长度** | 累加它会在缓冲区留下未写入的空洞 | 抓包可见用户名后约 23 字节垃圾 |
| 4 | **裸格式私有段的构造与解析**：`<type><len><content>` 串接；服务端段按 TLV 逐条走并做 GBK 解码 | 本接入点服务器下发的是裸格式；不做就只会看到"格式错误" | 报「字段格式错误，未发现特征值（偏移量 0x6）」 |
| 5 | **EAP-Success 找不到 echo key 时应降级**（例如用随机 echono 继续），而不是判失败 | 本接入点根本不下发 echo key，保活靠 Identity 轮询 | 服务器已放行却被本地判成失败 |
| 6 | **`heartbeat = 0` 时不发锐捷专有 echo，但必须在 Success 后应答服务器每 ~30 s 的 Identity 轮询** | 保活机制是身份轮询，不是专有 keepalive | 一段时间后被服务器认为掉线 |
| 7 | **Success 后不要复位状态机**（复位会丢会话信息），只清失败计数 | 状态机复位后无法应答轮询 | 会话无法保活；日志里能看到轮询无应答 |

### 1.1 与"离线调试"有关的一条（可选）

若要在**同一台设备上**用假认证器做离线回归（不接触校园网），raw socket 侧需要：
在"测试捕获模式"下把套接字绑到 `ETH_P_ALL` 并清 `PACKET_IGNORE_OUTGOING`，把过滤移到用户态
（只放 EtherType `0x888e`）。**该模式必须由环境变量门控**，未设置时行为与产线一致，否则会影响正常收发。

## 2. 关键配置项（两种已验证口径）

第三方实现（minieap 及广外适配分支）常见的字段与取值：

| 字段 | 含义 | 口径 A（较早的广外文档） | 口径 B（较新的稳定部署） |
| --- | --- | --- | --- |
| `module` | 数据包插件 | `rjv3` | `rjv3` |
| `eap-bcast-addr` | EAPOL-Start 目的地址 | 锐捷私有（`01:d0:f8:00:00:03`） | 锐捷私有（同左） |
| `dhcp-type` | 是否二次认证/DHCP 事务 | 二次认证 | `0`（不做额外专有二次流程） |
| `service` | 服务名 | `default` | `default` |
| `heartbeat` | 专有心跳间隔 | `60` | **`0`**（关专有 echo，靠轮询保活） |
| `if-impl` | 帧收发实现 | — | `sockraw` |
| `max-fail` / `max-retries` | 失败重试 | `3` | **`max-fail=1`**（一次失败就退出，避免烧反破解计数） |
| `no-auto-reauth` | 禁止自动重认证 | — | `1` |
| `fake-serial` | 序列号属性 `0x54` | 形如 `Static:<serial>` | 同左（本接入点未见校验，但建议与官方形态一致） |

> 两个口径都有人成功过；差别只在"专有心跳是否开启"。**先按口径 B 试**，若你的接入点确实下发 echo key 再考虑打开心跳。
> 注意：`eap-bcast-addr` 只影响 **Start**；有实现把"注销帧"也发往另一组地址，属实现不一致，排障时要留意。

## 3. 三个经典坑

1. **行尾**：在 Windows 工作副本上应用任何补丁/脚本时注意 CRLF（用 `core.autocrlf=false` 或在 LF 环境操作）。
2. **改了长度字段就一定要抓包复核**：EAPOL length 与 EAP length 不一致时，用普通抓包工具看"EAPOL len == EAP len"这一条即可发现。
3. **不要在开机时无条件发起认证**：认证次数是稀缺资源（见 `limits.md`）。让"认证"由显式策略/手动触发，并记账。

## 4. 建议的验证顺序

1. 离线：用假认证器验证两条私有段格式、长度同步、Success 后轮询应答（零校园网接触）。
2. 真机：只发一次认证，抓包确认 `EAPOL len == EAP len`、属性表与本文一致、服务器第二轮返回的是服务/计费段（而不是 `0x53`）。
3. 持续：把"认证成功"的判据建立在**客户端自身输出 + 日志新鲜度**上，而不是只靠探测（"认证成功但上不了网"是另一回事，见 `diagnose.md`）。
