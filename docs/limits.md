# 适用边界、风险与本笔记"故意不写"的东西

## 1. 适用边界

| 维度 | 覆盖 | 不覆盖 |
| --- | --- | --- |
| 校区/楼栋 | 广外南校区（大学城）宿舍有线口（本文所有"观察到"均来自此） | 其他楼栋、北校区、教学区、师苑等"网页认证"区域 |
| 网络类型 | 有线 802.1X（EAP-MD5 + 锐捷私有段） | 无线 `GDUFS` / `GDUFS-Auto` 的网页/Portal 认证 |
| 客户端代次 | 与 Windows 官方客户端 **V6.86 代次**相关的签名规格 | 其他代次（V4.96 等）需要另行分析；换版即失效 |
| 平台 | 任何能跑第三方 802.1X 客户端的 Linux 设备（本笔记实践载体是 OpenWrt 路由器） | 厂商固件（Padavan/梅林/原厂）需要另配工具链 |

## 2. 条款与风险（读之前请先读这一节）

1. **账号与设备**：本文面向"自己的账号 + 自己的设备"。学校明确禁止共享账号；本笔记不提供任何绕过账号体系的方法。
2. **在线设备数**：校方限制同一账号同时在线的设备数（本接入点口径为 3 台）。把认证做在路由器上会占用 1 个名额，请据此规划。
3. **反破解计数**：多次失败可能触发校方计数（社区口径约 10 次/日）。因此：
   - `max-fail` 保持 1，不做短间隔自动重试；
   - 自动认证设**每日硬上限**，建议 5–8 次（低于危险线），且手动重试单独小额度；
   - 断网/禁认证时段（工作日 01:00–05:00）不要发起认证；
   - 额度要**落盘**（掉电/重启不重置），否则计数形同虚设。
4. **设备时钟**：这类小路由器常无 RTC，掉电后时间回退。任何"按日期记账/按小时判窗口"的逻辑都必须先做**时钟有效性守卫**，否则会出现"当天额度被清零""半夜照常发起认证"。
5. **本笔记不保证**：任何具体实现能通过认证。它描述的是"官方客户端在这些接入点上的行为规格"，实现与调试仍需你自己完成并遵守校方条款。

## 3. 本笔记故意不写的内容

| 不写 | 原因 |
| --- | --- |
| 账号、口令、Wi-Fi 身份/密码 | 凭据 |
| **口令派生属性 `0x2f` 的任何取值** | 与账号强相关，属敏感信息；只记录"存在该属性" |
| MAC、序列号（`Static:<serial>`）、主机名、SSID、内网地址/网关 | 设备与机构标识 |
| 抓包文件与其字段 dump | 帧里含账号与身份信息 |
| 厂商二进制或其片段、以及从其直接复制的大段数据 | 版权与合规 |
| 具体某台设备上的部署脚本/包 | 与"知识"无关；且不同固件差别大 |
| 那处 8 字节块密码变换的算法 | 尚未复刻（只知确定性的输入/输出） |

## 4. 已知未验证项（不要当成结论）

1. 其他楼栋/校区是否同样适用（尤其是历史上被记为"无法认证"的楼栋）。
2. `0x35/0x36/0x38/0x39` 四条 IPv6 属性是否在某些接入点是**必需**的。
3. 变体 1 与变体 3 **没有官方会话锚点**（只有合成向量与内部自洽）。
4. `0x570340` 与 `Vz_API` 两条取模链的关系（两者下标不同）未确认。
5. 服务器是否只依据 `0x4d` 判定"管理员指定的客户端"，还是与 `0x2f`/会话状态联合判定。
6. 表数据的"生成过程"链条缺失（见 `tables.md` §3）。
