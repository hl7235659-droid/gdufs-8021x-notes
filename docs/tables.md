# 表数据：哪些能用公开来源，哪些必须自己提取

本文回答两个问题：**签名实现需要哪些表**；**每张表能不能从公开材料拿到**。

## 1. 总览

| 数据 | 维度/规模 | 来源 | 能否公开获取 |
| --- | --- | --- | --- |
| 变体分派公式 | — | 反汇编结论 | ✅ 见 `signature.md` §3（本仓库 `reference/` 里有实现） |
| 标准 MD5 的 `K`（64 个）、`S`（64 个） | 各 64 项 | 教科书常数（`K[i] = floor(2^32·abs(sin(i+1)))`） | ✅ 公式生成 |
| 改版 MD5 的**6 处 K 改写**与轮次安排 | 6 处 + 轮表 | 逆向结论 | ✅ 已在 `signature.md` §4 描述（列出改写点与轮次安排，不需要整表） |
| 标准 Tiger S 盒 | 4×256 × 8 B | 公开实现（如 minieap 的 `rjtiger_sbox.c`） | ✅ 与标准 Tiger **逐项相同**（已核对） |
| 4 个原语的自定义 IV | 5/4/6/8 个 u32 或 u64 | 逆向结论 | ✅ 属常量，已在 `signature.md` §4 说明其存在与作用位置 |
| **`MIXT` 混合表** | 8×64 个 u32 | 从客户端二进制提取 | ❌ **必须自备客户端提取** |
| **位切片打包/解包系数** | 2×129 / 2×65 组按位掩码 | 单比特探针提取 | ❌ 必须提取（探针方法见 §3） |
| **rjv3-Whirlpool 的 8×256 u64 表 + 11 条轮常量** | ≈16 KB + 88 B | 客户端 `.rdata` | ❌ 必须提取（其中 C0/C3/C7 有 63 字节偏离教科书） |
| **`WIN_V3_DIGEST_MD5/SHA1/TIGER` 三个摘要常量** | 16/20/24 B | 取自已打补丁的客户端 `.text` 镜像 | ❌ 必须提取（等于镜像某一处变换后的摘要） |
| **那 8 字节块密码的输入/输出对** | 8 B | 运行时观测 | ⚠️ 输入 `0000005081ec8c00` → 输出 `853eac23ac4931ff` 已确认确定性；**算法未复刻**，实现时按同样方式从自备客户端取 |

## 2. 结论："实现到哪一步需要什么"

```
分派 + 输出切分        ← 公开（本笔记）
四个原语的骨架与 IV    ← 公开（本笔记）
标准表（MD5 K/S、Tiger S 盒） ← 公开来源/公式
──────────────────────────────────────────
MIXT、PACK/UNPACK、Whirlpool WCT/WC_RK、三个摘要常量 ← 必须自备客户端提取
那 8 字节密文（或等价变换）                          ← 必须自备客户端取得
```

也就是说：**本笔记让你知道"要提取什么、提出来放在哪、怎么用"；不提供提取结果。**

## 3. 提取方法

完整流程（输入 → 步骤 → 输出 → 自校验点）见 **[`table-generation.md`](table-generation.md)**。一句话概括：

1. **定位**：按已知锚点找到表区与相关函数（Whirlpool 的 8×256 u64 表与 11 条轮常量；`MIXT` 与位切片变换函数；Tiger 的 key schedule 常量）。
2. **提取**：对"按位线性"的打包/解包用**单比特探针**（每次只让一位为 1）取系数；对轮逻辑用反汇编得到有序步骤表再机械展开；Tiger 的 S 盒与标准 Tiger 相同，**无需提取**，用公开实现即可。
3. **自校验**：全零输入必须得到全零输出（证明无常数项）；再抽查 padding 二块分支与块边界；最后把 `../vectors/vectors.json` 全部打中。

> 本笔记给出**方法**而非数据：`.text` 镜像、提取出的表、以及客户端任何片段都不随本仓库分发（见 `../docs/limits.md` §3）。

## 4. 失效条件（与 `signature.md` §7 一致）

客户端版本变化时，上述"必须提取"的四类数据都可能变。判断是否失效的最快方法：拿一条官方会话的
`(挑战 → 0x4d)` 对照你的实现；如果对不上，先怀疑表而不是算法结构。
