# 失败模式对照表

按"看到什么 → 大概率是什么 → 怎么办"组织。表中所有文本均为服务器下发的 GBK 提示原文（诊断必需，故保留）。

## 1. 认证阶段

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 日志：`字段格式错误，未发现特征值（偏移量 0x6）` | 客户端在按"封装格式"解析**服务器的裸格式**私有段（缺 magic） | 实现裸格式解析（`protocol.md` §2.1）。若实现已支持仍复现，见 §3「楼栋差异」 |
| 服务器下发 `0x53` + `未使用锐捷客户端!` | 客户端形态被拒（典型：Start 形态/私有段位置不对） | 核对 Start 与私有段只加在 MD5 应答上 |
| 服务器下发 `0x53` + `锐捷客户端版本过低!` | `0x11` 属性里的版本字节与官方不符 | 把 `0x11` 的内容做成官方形态：`"8021x.exe"` + 补零 + 正确版本字节 |
| 服务器下发 `0x53` + `使用了非管理员指定的客户端!` | **客户端签名 `0x4d`/`0x60` 不对**（变体分派错、表过期、那 8 字节镜像变换未复现） | 见 `signature.md`；先用 `vectors/vectors.json` 自测分派，再核对表与镜像 |
| 服务器下发 `0x53` + `您前一次上网没有正常下线!为保证您的账户正常,请再认证一次!` | 会话状态类（上次会话未正常释放） | 等会话释放再试（有实现用"最小认证间隔"规避），不要连点 |
| 服务器下发 `0x53` + `不在认证时段内` | 命中校方断网/禁认证时段（本接入点为工作日 01:00–05:00） | 在时段判定里跳过认证并把这次尝试**不计入额度**；不要在窗口边界抢跑 |
| 没收到任何 EAPOL 回复 | 端口未授权/链路未就绪/交换机未放行 | 先确认 carrier 与端口，再看抓包 |
| 认证过程中客户端自己退出 | `max-retries` 设得比实际流程短 | 放宽到 `3`，但 `max-fail` 保持 1 |

## 2. 认证成功但"上不了网"

这是本接入点**最容易被误判**的一类，不是认证问题。

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| EAP-Success，但 ping 网关/外网 100% 丢包；抓包可见网关主动 ARP 查询、我们应答后**仍反复重查** | 交换机侧 **DHCP snooping + DAI/IPSG** 按 **DHCP 事务**维护 IP↔MAC 绑定；静态 IP 没有 DHCP 记录 → IP 报文被静默丢弃（EAPOL 不受影响） | 用**一次性 DHCP 事务**刷新绑定（只做 DISCOVER/REQUEST、不改本机静态配置）。触发点建议：认证成功后出口不通、撤路由前、稳态每 6 小时一次 |
| 首次解析慢、部分域名超时 | DNS 服务器顺序/DNS 与探测目标耦合（探测目标同时当 DNS） | 把健康探测目标与 DNS 解耦；探测用"多目标 + 多协议"，别用单一 ICMP 目标 |
| 认证成功但很快掉线 | 客户端复用了**上一轮的日志**判定成功（旧内容仍写着"认证成功"） | 判定要求"本轮日志 + mtime 晚于本轮开始"；服务启动前先截断日志 |
| 会话仍在线却被反复重认证 | 同上（存活判定失灵）导致重复登录 | 有"会话在线"证据（轮询应答）时**不要**重认证；并设最小认证间隔 |

## 3. 楼栋/接入设备差异

同一所学校、不同楼栋可能落在**不同型号的接入设备**上，导致同一条客户端报文被拒。已知表现与处置：

| 现象 | 处置 |
| --- | --- |
| 某些楼栋始终 `0x6` 或 `0x53`，别的楼栋正常 | 1）先用**同步抓包**确认"官方客户端在该楼栋发的帧结构"与你的实现是否一致（重点比：Start 形态、Identity/MD5 的目标地址、第二轮请求的**服务器侧**段是不是服务段）；2）在若干楼栋验证过的处置是 **WAN 用静态地址 + 克隆一台已成功认证设备的 MAC**；3）仍不行则记录"楼栋 + 失败句 + 帧差"，回帖补充（见 `limits.md`） |

> 提示：这条正是社区里长期无解的那一段（"同校不同楼栋报文结构不同"）。任何**新的楼栋结论**都比算法本身更有价值，欢迎反馈。

## 4. 次数与额度

| 现象 | 处置 |
| --- | --- |
| 连续失败若干次后，连正常配置也开始被拒 | 可能触发校方反破解计数（社区口径：每天约 10 次量级） | 停手、等计数窗口过去；把自动重试**硬上限**压在危险线以下（见 `limits.md`） |
| 手动重试把额度烧光 | 手动通道也要独立记账，不要"手动不计次" |
