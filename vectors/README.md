# 测试向量

`vectors.json` 收录 **7 组**（挑战 → 期望摘要），分三类：

| class | 数量 | 可信度 | 用途 |
| --- | --- | --- | --- |
| `official` | 3 | 强：官方客户端成功会话 | 判断实现是否正确（**这是唯一能证明"与官方一致"的证据类型**） |
| `live` | 1 | 中：真机第三方客户端、服务器接受 | 证明服务器放行；不证明与官方逐字符相同 |
| `synthetic` | 3 | 弱：合成/自洽 | 防回归、覆盖 5 个变体（其中 variant 1、3 **没有**官方锚点） |

## 怎么用

```sh
# 1) 只校验"变体分派"（自包含，无需任何厂商数据）
python ../reference/variant_dispatch.py

# 2) 校验完整摘要（需要你自备同代官方客户端）：
#    把向量的 challenge 喂给你的实现，与 expected_digest_hex 逐字符比较。
#    复现条件与所需数据见 ../docs/tables.md、../docs/signature.md §2
```

## 安全声明

- 本目录**不含**账号、口令派生值（如属性 `0x2f`）、MAC、序列号、抓包或厂商二进制。
- 挑战值是服务器每次下发的随机 16 字节，摘要由"挑战 + 客户端镜像"决定；因此这些向量可安全公开。
- 若你要新增向量，请遵守同样的边界：**不要**把含账号/身份信息的抓包字段搬进来。
