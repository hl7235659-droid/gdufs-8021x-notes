# 广外（GDUFS）有线 802.1X 认证 —— 协议与实现笔记

这份笔记记录的是一台宿舍路由器在本校**有线网络**上完成**锐捷 802.1X 认证**所需的知识：
报文格式、客户端签名校验的规格、已知失败模式、以及已经确认的修复点。

**它刻意不包含任何可执行发布物**：没有 ipk、没有安装脚本、没有厂商二进制、没有抓包、没有账号/口令/MAC。
"怎么把它装到自己的路由器上"由读者配合上游开源项目自行组装（起点见 `docs/implement.md`）。

---

## 适用范围与验证程度

| 项 | 内容 |
| --- | --- |
| 环境 | 2026-09，广东外语外贸大学南校区（大学城）宿舍有线口 |
| 认证方式 | 标准 802.1X / EAP-MD5，外层套锐捷（RJv3）私有段 |
| 已验证 | 真机长时间在线（含服务器每 ~30 s 的保活轮询）；客户端签名的 **5 个变体**在离线侧与官方客户端逐字符对齐；其中 **variant 0 有官方会话锚点**（见 `docs/verification.md`） |
| 未验证 | 其他楼栋/其他校区的接入设备差异；换用新版官方客户端后需要重新提取表 |
| 不包含 | 任何抓包、厂商文件、凭据、设备标识（MAC/序列号/主机名/SSID） |

## 目录

| 文件 | 内容 |
| --- | --- |
| `docs/protocol.md` | 认证时序、两种私有段格式、属性表、保活、两轮认证、服务器提示文本 |
| `docs/signature.md` | 客户端签名（128 hex 的 `0x4d`/`0x60`）：变体分派、输入、4 个分组原语、位切片变换、输出拼装 |
| `docs/tables.md` | 哪些表可以用公开来源、哪些必须从你自备的官方客户端提取；失效条件 |
| `docs/table-generation.md` | 表的**生成链**：从自备客户端出发的 6 个阶段、每步自校验点、三个发布陷阱 |
| `docs/implement.md` | 接进 minieap 的 7 条**行为学**要点（不是补丁文件）、配置参数、三个经典坑 |
| `docs/diagnose.md` | 现象 → 原因 → 处置对照表（含 `0x6`、`0x53` 各句、"不在认证时段内"、"认证成功但上不了网"） |
| `docs/limits.md` | 适用边界、条款与风险、本笔记**故意不写**的东西 |

| `reference/` | 可直接运行的参考实现（变体分派 + 向量自测） |
| `vectors/` | 挑战 → 期望摘要的测试向量（官方 4 组 / 合成 3 组） |

## 给"只想把它做出来"的读者

1. 按 `docs/protocol.md` 把**两种私有段格式**做对——尤其"追加私有段后必须同步 EAP/EAPOL 长度字段"这一条，它是历史上真正的根因。
2. 按 `docs/signature.md` 实现客户端签名（变体分派 + 5 个变体）。
3. 表按 `docs/tables.md` 从**你自己的那份官方客户端**里提取（本笔记不提供表数据）。
4. 上线前用 `docs/diagnose.md` 过一遍失败模式；用 `docs/limits.md` 确认你在适用范围内。
5. 跑 `python reference/variant_dispatch.py`，用 `vectors/` 里的向量自测分派逻辑（摘要比对需要你自备客户端镜像，见 `reference/README.md`）。

## 免责与合规

- 本笔记面向"用**自己的账号**、在**自己的设备**上完成认证"的用途，属协议学习与互操作性研究。
- 请遵守所在校园网的使用条款；**不要共享账号**；按学校规定的在线设备数使用。
- 认证失败次数较多可能触发校方的反破解计数（社区口径：每天约 10 次量级），因此任何自动重试都应当有明确上限——本笔记在 `docs/limits.md` 里给了建议值。
- 本笔记不含厂商二进制或其片段；`docs/signature.md` 中的常量是"对某一版本官方客户端逆向所得的规格"，**随客户端版本变化即失效**。
